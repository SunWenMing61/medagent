## 故障归因

四种故障标记允许重叠：

| 故障类型 | 数量 | 比例 |
|---|---:|---:|
| 检索失败 | 0 | 0.00% |

本次10条“回答幻觉/引用无据风险”全部来自同一个可复现问题：模型虽然在回答中写出了正确的 `ev_fixed_*` 证据编号，但没有使用系统要求的 `[ev_fixed_*]` 方括号格式。因此确定性引用校验器无法把声明绑定到检索证据。此次没有检测到测试集中明确标注的错误/禁用事实。

4条工具错误分别是：

- `get_medical_table` 未调用；
- `get_document_evidence_context` 未调用；
- `fda_drug_label` 未调用；
- `pubmed` 未调用。

原因是当时启用的是旧版工作流，所有需要知识来源的问题都统一走 `local_knowledge_base`，没有进入受控专用工具选择链路。

## 结论

1. **Top-5已找齐全部标注证据**：10个检索题固定返回50条结果，测试集一共只标注11条相关证据，因此Precision@5的理论上限就是11/50=22%。当前结果正好命中全部11条，不能据此判断检索质量差。更有区分度的结果是Precision@1=90%、Recall@1=85%、Precision@3=33.33%、Recall@3=90%、MRR=92.5%。10题中9题的正确证据排第1，仅FAST卒中题排第4。
2. **回答内容完整，但引用协议不合格**：12条题目的必答要点均完成，没有任务中断；严格准确率低主要不是答案遗漏，而是引用格式未通过机器校验。
3. **当时专用工具路由尚未生效**：旧版链路无法正确选择表格、相邻上下文、FDA标签和PubMed工具；该链路现已删除。
4. **此报告可作为后续基线**：以后修改Prompt、模型或检索策略后，应在相同测试集SHA-256下重新运行，并与本报告对应的JSON基线比较。

## 评测边界

- 本次使用隔离内存索引，不测试生产pgvector SQL、租户权限过滤、数据库延迟或线上数据分布。
- Precision@K受每题标注相关证据数量和固定返回条数影响；本测试集大部分题目只有1条相关标注，所以应与Recall、Hit Rate和MRR联合解读。
- 测试集是固定合成工程回归集，不代表临床有效性，也不是医学执业能力测评。
- 本次只运行一轮，温度0.5可能带来少量生成波动；重要版本建议重复运行并观察稳定性。
- “回答幻觉/引用无据风险”是严格工程定义，包含引用格式不合规；不等同于10条回答都出现了错误医学事实。

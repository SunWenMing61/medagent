# Redis 高频标准答案缓存

该缓存位于聊天 API 与受控 Agent 工作流之间。首次可复用的标准问题正常执行混合
检索、证据核验、回答生成和安全审核；只有状态完整、证据充分、引用存在且安全审核
通过的答案才写入 Redis。相同问题再次出现时直接返回已审核答案和引用，避免第三方
模型与工具重复调用。

## 安全边界

- 仅启用普通问答助手、创建新会话并选择了知识库时参与缓存。
- 记忆问答、多轮会话、包含患者个体症状/检查值/剂量的问题自动绕过。
- 租户、知识库范围、文档更新时间、文档数量、块数量、模型和检索参数都进入 SHA-256 缓存键。
  文档更新或重新向量化后，旧缓存不会再被命中，并在 TTL 到期后自动删除。
- 修改提示词但不修改模型/检索参数时，应同时提升 `STANDARD_ANSWER_CACHE_VERSION`，
  防止新旧提示词共享缓存。
- 不缓存证据不足、无引用、安全未通过、需要追问、需要人工审核或执行出错的回答。

## 并发与可用性

Redis `SET NX EX` 锁用于热点问题防击穿。第一个请求执行模型调用，其余并发请求短暂
等待并复用第一个请求写入的答案。Redis 不可用时聊天链路 fail-open，正常执行 Agent，
不会因为缓存故障阻断问答。

## 指标

`GET /api/chat/cache/metrics` 返回命中率、冷请求/命中核心链路耗时、模型调用执行与
避免次数、估算模型调用减少比例、累计节省耗时和并发等待复用次数。前端“检索调试
与可观测性”页面直接展示这些实际运行数据。

图片中的“响应提速 40%、模型成本降低 60%”被视为运营目标，不是硬编码结果。部署后
应以真实流量指标判断是否达到目标；没有足够命中样本时页面显示 0，而不是虚构数值。

# 多 Agent 改造审计

## 改造前的关键问题

| 问题 | 风险 | 本次处理 |
|---|---|---|
| 顺序式 `MedAgentWorkflow` 同时承担路由、检索、生成和聚合 | 职责不清，无法独立评测 | 删除旧入口，只保留唯一 Supervisor 和独立子图 |
| 每个知识库直接生成答案后再聚合 | 未核验证据可进入结论 | 改为检索结果标准化、去重、融合、核验后再生成 |
| 会话历史和医学证据边界不明确 | 历史回答可能被当作事实 | 会话记忆独立表和工具，仅作上下文，不允许支持医学主张 |
| Agent/Tool 无统一调用预算 | 重试或路由错误可能形成循环 | Agent 6 次、Tool 10 次、检索重试 1 次、安全改写 1 次、总超时 45 秒 |
| 无可恢复的 Agent 状态 | 中断后无法澄清或审核 | `agent_run` + 版本化 checkpoint + clarification/HITL 恢复 API |
| Trace 无法区分规则和模型调用 | Token/成本审计不准确 | 规则 Agent 记录 `deterministic-rule-v1`、0 token、0 cost |
| 前端只消费回答 token | 用户看不到工作流阶段 | 展示分诊、检索、证据核验、安全审查、人工审核等公开事件 |

## 当前运行策略

所有聊天入口统一进入受控图，本地知识库只能通过 `local_knowledge_base` 工具调用 HybridRetriever。聊天附件直读提示词和 multipart 问答已移除；文档必须先上传、清洗、向量化入库，再参与混合检索。

## 明确不做的事情

- Agent 不直接执行 SQL，也不能发现或调用其他 Agent。
- 在线医学来源失败不会伪装成“无证据”。
- 不保存或展示私有思维链。
- 示例评测不标记为临床基准或线上实测。
